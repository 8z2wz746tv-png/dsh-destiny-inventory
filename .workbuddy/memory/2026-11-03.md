## 白屏根因与修复（13:10 完成，待用户重启验证）

**现象**：侧栏「命运仓库」有行、点击后主区全空；`.dsh-destiny-legacy` 查询为 `none`；Console 无报错。

**根因**：DSH 桌面端渲染进程是 `sandbox: true` + `contextIsolation: true` + `nodeIntegration: false`（main.js webPreferences），页面里没有 `process` 全局。而 `noExternal` 把 `@tanstack/react-query` 打进 client bundle 后，rolldown 没有折叠 `process.env.NODE_ENV`，产物里残留 10 处（全部来自 query-core），其中一处在 `useBaseQuery()` 第一行 → 首次渲染即 `ReferenceError: process is not defined`。宿主 `SlotErrorBoundary.componentDidCatch` 只打一行 `slot entry crashed in 'main'` 就 abdicate，之后永远渲染空的 `data-slot-error` 占位 —— 表现就是"空白 + 无报错"。

**修复**：
1. `tsdown.client.config.mjs` 加 `define: { 'process.env.NODE_ENV': '"production"' }`。构建后 `lib/client.js` 中该表达式 0 处。
2. `src/client/LegacyInventoryPanel.tsx` 增加 `PanelFailureBoundary`（class 组件，`getDerivedStateFromError` + `componentDidCatch`），失败时在面板内输出错误名/消息并给「重试」按钮；`styles.ts` 加 `.dsh-destiny-panel-error` 样式。目的：任何渲染期异常不再表现为静默空白。

**构建注意**：本项目不能用 `pnpm build` / `pnpm exec`——pnpm 的 deps-status 检查会自己跑 `pnpm install` 并失败（exit 251 / 进程被 137 杀掉）。直接用 `./node_modules/.bin/tsdown`、`./node_modules/.bin/tsdown --config tsdown.client.config.mjs`、`node scripts/wrap-client.mjs`。

**重新安装**：新 tgz sha256 `1a4d151bb5b48957445ae90606e2f2e1ebfb09987ea7a30b82710aeb8b5c8945`，缓存到 `~/.dsh/dsh-destiny-inventory/pkgs/<sha>/`，用 `/tmp/dsh-install-destiny-inventory.mjs <file:spec>` 跑内部管线。验证：dep spec 已更新、bundles 仍含插件、已安装 client.js 无 process 残留且含边界。

**仍存在的第二个阻塞**：面板数据走 `http://127.0.0.1:37511/api/webui/inventory/*`，该 sidecar 现在完全没起（curl 返回 000，此前是 502）。所以重启后预期看到的是页面骨架 + 连接失败提示，而不是仓库内容。要真出数据，得二选一：起 sidecar，或把 `src/client/legacy/lib/api.ts` 改成打宿主半已有的 `/dsh-destiny-inventory/{inventory,item,characters,action}`（路径与载荷形状都要适配）。
