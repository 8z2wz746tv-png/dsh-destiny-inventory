# 搜索方案：中文名 + Perk 名，不引入查询语法

## 判断

DIM 的 152 个关键词是给"用键盘管 5000 件东西"的人准备的。我们的实际用法是**想起一件东西，找它**——所以搜索要回答两件事：

1. 我叫得出名字 → 按名字找
2. 我叫不出名字，但我记得它有个 perk → 按 perk 找

不做的：`is:` / `stat:` / 范围 / 布尔 / 否定。这些等真的需要了再说。

## 匹配什么

一个输入框，按四类权重匹配：

| 权重 | 匹配的字段 | 例子（输入「快速」） |
|---|---|---|
| 1 | 物品名 | 「快速拔枪」这把枪本身 |
| 2 | 当前装着的 perk 名 | 任何装着「快速拔枪」perk 的枪 |
| 3 | **可切换的** perk 名（组件 310 的候选池） | 能换成「快速拔枪」的枪 |
| 4 | 武器类型名 + perk 描述 | 「手炮」「提升装填速度」 |

权重只影响排序，不影响是否命中——搜到了就是搜到了，只是好的一排在前。

**多词**：空格分隔，按"全部命中"处理（AND）。中文不分词，整串做子串匹配。

```
输入「手炮 快速」
→ 手炮里，名字或 perk 命中「快速」的
```

## 数据从哪来

**不需要新接口**。`/details` 已经把所有东西送到客户端了：

```
ItemDetailView {
  name, weaponType, description,
  intrinsic { name, description },
  columns: [{ slot, options: [{ name, description, selected }] }]
}
```

现在的问题是这份数据只在悬停时用。搜索要读它——**建一次索引**。

## 索引

```ts
// src/client/search-index.ts
interface Entry {
  id: string
  /** 已小写化的检索文本，用 \u0000 连接，避免跨字段误命中 */
  haystack: string
  /** 名字单独一份，用来给权重 1 */
  name: string
}

buildIndex(items: ItemRow[], details: Record<string, ItemDetailView>): Map<string, Entry>
```

建索引的成本：1924 件 ×（名字 + 类型 + 约 20 个 perk 名）≈ 4 万字符串拼接。实测应该在 **20–50 ms**，一次性，在 `/details` 到达后建。

搜索本身：4 万条 `String.includes` ≈ **2–5 ms**，每次按键跑都够快，不用防抖也感觉不到。

## 排序

命中的物品按这个顺序排：

1. 名字命中（且位置越靠前越好）
2. 当前 perk 命中
3. 候选 perk 命中
4. 类型 / 描述命中

同权重内沿用当前选的排序（光等/名称/类型）。

## 界面

现在的搜索框留着，只是行为变了：

```
[搜索名称]     →     [搜索名称或特性]
```

占位符改一句话就够了。不加语法提示、不加下拉建议——用不到。

## 不做

- **不做** `is:dupe` 这类筛选词。真要"找重复"就加个按钮，不是让人背语法。
- **不做**拼音/首字母。你的输入是中文，直接子串匹配；拼音要引一个几百 KB 的库。
- **不做** 高亮命中片段。第一版先把"找到"做对。

## 验收

1. 输入「星火」→ 术士胸甲「星火协议」排第一
2. 输入「快速拔枪」→ 装着或能换成这个 perk 的枪全部出现
3. 输入一个只存在于 perk 描述里的词 → 相关武器出现
4. 输入不存在的词 → 空列表，不是全量
5. 1924 件下，每次按键到列表更新 < 100 ms（目测无感）
