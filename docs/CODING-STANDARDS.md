# 通用编码规范（可移植骨架）

从本仓 `AGENTS.md` 提炼的跨项目版本。本仓冲突时以 `AGENTS.md` 为准。

> 每条给 **规矩 / 为什么 / 怎么守**；能自动化的一律配守门测试。

## 0. 三条总原则

- **单一出处**：一个事实只写一次，其余地方引用。
- **不许静默降级**：降级、跳过、探测失败都留痕，不许伪装成正常结果。
- **不许做兼容层**：不为旧形状留双写、过渡分支、失败回退；要改就改到底。

## 1. 协作方式

| 规矩 | 为什么 | 怎么守 |
|---|---|---|
| 大改动先给计划，确认后一次做到位 | 反复确认把时间耗在流程上 | 计划文档 + 阶段清单 |
| 汇报按「干了什么 / 现状 / 准备怎么做 / 结果」 | 读者要"看过去就了解情况" | 同一事实只说一次 |
| 先答问题本身 | 别让人从过程里找结论 | 首句给判断 |
| 不许拿估算当结论 | "应该/大概"会被当成事实往下传 | 数字必须来自实跑，附命令 |
| 报告写"没验成的部分" | 防"调用成功"冒充"功能正确" | 显式列未验项 |
| 结论带原文（报错、回执、日志行） | 转述必失真 | 引用 ≤ 若干行 |
| 别人的结论写进自己产物前先复现 | 一句抄错的常量能连红好几轮 | 自己跑一遍 |
| 只修真实咬到的问题 | 否则项目永远修不完 | 待办只留咬人的 |

## 2. 单一出处 + 守门测试

- 一张表、一份映射、一段正则、一句口径，只允许一处；共享就抽模块。
- 每个唯一出处配一条**"禁止再抄"**的扫描测试（发现第二份就红）。
- 结构性口径由脚本生成，手写会被覆盖；生成物进 CI 比对。
- 说明里承诺的每个取值都必须能被代码解析。

## 3. 不许静默降级

- 没算就不能说：结论只说自己算过的东西。
- "没探成" ≠ "试过没有"：失败要 `ok: null` + reason，不能记成 false。
- 结论路径的 `except` 必须留痕（重抛 / 写返回值 / 打日志）；空 except 算 bug。
- 可选数据可降级，但必须带 warnings。
- 缺值给 `null`，不编 0。

## 4. 禁止兼容层与补丁

- 改接口形状：旧键一个不留。
- 别名要么永久（用户口语），要么登记待删。
- 旧实现整段删掉，不保留"失败退回旧路径"。
- 破坏性变更在提交标题点名。

## 5. 分层、依赖方向与体量

- 依赖只能向下，禁止环；每个顶层模块登记层号。
- 服务容器的每个 key 必须声明，测试扫"用了但没声明"。
- **模块超限先抽代码，不抬上限**（ratchet）。

## 6. 失败、写入与数据分档

- 失败必须是失败：`ok=false` + 稳定错误码 + 人话说明。
- 写操作：签发候选 + 用户确认才写；写完回读；回读失败只能报 unverified。
- 数据分档不许混：权威定义 / 用户数据 / 第三方社区数据（带来源与时间）。

## 7. 测试与验证

- 单测绿 ≠ 真机对，两者都要。
- 每个守门测试要注入一次违规确认变红，再逐字节恢复。
- 夹具形状必须来自真实现，不许手编。
- 测试不许依赖开发机环境（两种环境都要过）。
- 改完先验产物：进没进包 → 有没有执行 → 值对不对 → 才到肉眼。

## 8. 注释与提交

- 注释写**为什么**（根因、踩过的坑），不写"做了什么"。
- 口径写进可执行断言，不靠人记。
- 密钥永不进日志、提交、截图。
- 打包前先提交，版本号与提交一一对应。

## 9. 文档索引

- 所有文档登记一处，每条一句话说"什么时候该看它"；双向核对。
- 代码地图由脚本生成，手改判红。
- 架构决定单独记 ADR（只记决定了什么和为什么）。

## 10. 协作型 agent

- 异步子任务无法中途追问 → 派活时把要求写全。
- 同一文件被并发改时用最终字节裁定（shasum）。
- "进程比提交新"有盲区：核 `mtime` vs 进程启动时间。

## 11. 新仓库第一天

AGENTS.md + README.md + CHANGELOG.md；唯一出处表；分层表 + 体量上限；错误码唯一出处；文档索引一致性测试；代码地图生成脚本；兼容面台账；真机脚本与单测分开。
