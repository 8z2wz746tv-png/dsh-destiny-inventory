### F5 实测（用一个独立的浏览器实例，不是桌面端）

三次数：

| 场景 | 缓存上屏 | 最新数据 |
|---|---|---|
| 首次打开（无缓存） | 无 | 2319ms |
| F5 后 | **42ms** | 1430ms |
| 造一次写入后立刻 F5 | **16ms** | 1415ms |

**42ms 对比 2319ms 就是 P2 的全部意义。**

**F5 之后真正发生的事**（第三次实验，用 curl 写入 + 立刻刷新）：

```
journal:  超星系团 vault → hunter  ok      ← 写入成功
Bungie:   vault  → vault → vault → hunter  ← 20s / 40s / 60s 之后才纠正，80s 才变
面板:     显示 vault                        ← 缓存与"最新数据"都是旧位置
```

所以 F5 的真实表现是：**物品停在原处，看起来那次拖拽根本没发生，最长约 80 秒**。

**同步窗口实测 60–80 秒**，比此前记录的 56–64 更长。`detect-external` 的 90 秒上限仍然覆盖。

**一个反直觉的后果**：缓存让这个"错误"出现得**更快**（42ms 而不是白屏 2.3 秒）。
以前是等，现在是很快看到一个错的位置。诚实的说法是：缓存没有制造错误，它只是把
Bungie 的滞后提前暴露了——而时间戳（「X 分钟前更新」）是唯一能说明"这是旧数据"的东西。

### 没验的

- **在浏览器里真实拖拽后再 F5** —— 浏览器工具无法派发 HTML5 拖拽事件，上面第三次实验用
  curl 写入代替，因此**没有 overlay**，测不到「overlay 丢了」那一半。逻辑上 `pending` 是
  `useMemo` 内存对象，页面重载必然重建为空。
- **切换 Bungie 账号** —— 只有单测，没有第二个真实账号可切。

  按面板的规则算出来「应该画在 hunter」。

### 没验到的

**没亲眼看到未确认环**。猎人的护甲区在页面很下面，滚动两次只到武器区，
搜索框点错成了侧边栏的会话搜索。所以「恢复后显示目标位置 + 环」这一条：
数据链路对，**渲染层没有目视确认**。

### 这一轮发现的真 bug（已修）

`restoreIntents` 原本写在缓存分支**里面**。第一次用这个浏览器实例打开时 IndexedDB 是空的，
缓存分支整个跳过——journal 里明明有一条可恢复的意图，控制台只有「最新数据」，
什么都没挂回去。

修法：恢复与缓存解耦。没有缓存时也恢复，只是没东西可重画，意图留在内存里等网络答案。
测试注入空缓存并断言 `restoreIntents` 仍被调用。

## 六项真机验收

每项都写清楚：怎么造、看什么、什么算通过。**跑之前先确认宿主加载的是当前构建**
（`./dev.sh` 之后若动过 `src/host/` 要重启；只动 `src/client/` 等 500ms 热更或 `Cmd+R`）。

### V1 · 仓库 → 角色，操作成功

**造**：面板上把一件仓库里的武器拖到猎人。
**看**：物品立刻出现在猎人列；回执显示"已移到角色背包"；**等 90 秒**再刷新，仍在猎人。
**通过**：全程没有跳回仓库。

### V2 · 移动后立即刷新（本条是 P1.3 的核心）

**造**：拖完一件，**立刻**（1 秒内）点工具栏的刷新。
**看**：物品还在目标位置。
**通过**：不跳回。
**失败的样子**：物品闪回仓库，几秒后又跳回来 —— 那就是 overlay 没生效。

### V3 · 连续移动同一件 A → B

**造**：把同一件物品先拖到术士，2 秒内再拖到猎人。
**看**：最终停在猎人；回执两条都在；没有"先回术士再回猎人"的闪动。
**通过**：A 的旧回执没有把物品画回术士。

### V4 · 移动后结果不明

**造**：断开网络后拖一件（或在拖拽中途杀进程/切离线）。恢复网络。
**看**：物品停在目标位置，带未确认环；回执显示失败原因。
**通过**：**不回滚**，并且带 `unconfirmed` 标记；不知道就是不知道。
**备注**：这条最容易造错 —— 要在**请求在途**时断网，不是拖之前。

### V5 · 页面连续刷新不产生重复转换

**造**：拖一件，然后在同步窗口内连点刷新 5 次。
**看**：回执不重复出现；物品位置不变。
**通过**：没有重复的状态转换（P1.5 之后表现为 journal 里不多出记录）。
**现状**：`transitions` 目前被丢弃，所以只能验证"UI 不抖"。journal 侧要等 P1.5。

### V6 · 页面刷新后重新加载

**造**：拖一件，**立刻按 F5**。
**看**：物品显示在……同步窗口内会显示旧位置。
**通过**：**这项现在预期"不通过"** —— overlay 是内存状态，F5 丢掉是已接受的设计。
在 P1.5 的恢复机制做出来之前，**不许**对外说跨刷新可靠。
