# 现在到哪了：对照 PLAN-SELF-HOSTED-DIM 的四个阶段

写于 2026-11-06，v0.45.1。

## P1 数据面 —— 完成

| 计划要求 | 实际 |
|---|---|
| OAuth 独立应用 | **没做**，读 MCP 那份 token（`token-file-provider.ts`，只读不刷新） |
| GetProfile 带全组件 | 做了。102/201/205/300/304/305/309/310 |
| Manifest 定义层 | 做了。读 MCP 的 sqlite |
| 1900+ 件、桶分类正确 | 真机验证过 |

**与计划的偏离**：没有独立 OAuth。这带来一个真实约束——**token 过期要 MCP 去续**。单人用没问题，但它不是计划里那个形态。

## P2 写入面 —— 约 70%

| 计划要求 | 实际 |
|---|---|
| 四个动作 | 完成：move / equip / lock / pull_postmaster |
| 拖拽即执行、不弹确认 | 完成 |
| **先本地乐观改，再发请求** | **没做**。现在是"成功后才改"（跟 DIM 一致，跟计划相反） |
| **失败按快照回滚** | **没做**，因为不是乐观 |
| **串行化写队列** | **没做**。`busy` 只是个界面标志，不防并发 |
| 写后轻量回读 | 半做：`invalidate()` 让下次读拿到新的，没有主动回读校验 |
| 回执可点开 | 完成（带图标、可取消、成功 5 秒消失） |

**两个真实缺口**：

1. **没有写队列**。连续拖两件同一物品，两个请求会同时在途，Bungie 没有事务，结果可能是幽灵状态。计划 §3.3 把这条列为"必须"，我漏了。
2. **计划要的"乐观"和 DIM 的做法冲突**。计划说"先改再发，失败回滚"；DIM 是"等成功再改"。我读了 DIM 之后选了 DIM 的方式，但没有回去改计划——所以文档和代码现在是矛盾的。

## P3 上下文 + 预设 —— 0%

计划要的三样，一样都没有：

- 两个只读工具（"我现在选了什么"/"这件怎么样"）→ 没有 `ctx.tools.register` 调用
- journal（写入流水，带 `source: 'dim' | 'agent-detected'`）→ 没有
- `destiny` preset + 浮动聊天框 → 没有

**这一层是"随航 agent"的全部内容**，也是这个项目最初的立意。现在面板是个独立的 DIM 替代品，agent 完全不知道你在里面做了什么。

## P4 —— 部分

- 模组写入（`InsertSocketPlugFree`）：没有
- 套装/属性条：属性条有，套装没有
- 搜索语法：**用户明确不要**，改成"名字 + perk 名"（`docs/PLAN-SEARCH.md`）

## 地基结论

**"看"和"动"的地基完成了**：数据面稳、写入面能跑、界面能拖。

**但有两块承重没打**：

1. **写队列**——这是并发正确性问题，不是功能。越晚补越痛，因为所有写入路径都得改。
2. **上下文层（P3）**——这是"随航"这个产品定义本身。

## 建议顺序

1. **写队列**（半天，结构性，先补）
2. **搜索**（一天，日常收益最大，方案已定）
3. **P3 上下文**（两三天，回到项目立意）

标记、批量、插槽可点那些可以放在这几件之后。
